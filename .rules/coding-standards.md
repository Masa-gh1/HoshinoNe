# ほしのね プロジェクト コーディング規約

## 基本方針
- 天体写真処理に特化したビジュアルフローエディタ
- 日本語コメントを使用
- 計算結果精度とパフォーマンスを重視
- 速度が優先される一時的な画面表示は近似値を許可(例:ヒストグラムなど)

## コーディングルール
- クラス名:PascalCase(例:OffsetNode)
- メソッド名:camelCase(例:detectStars)
- 変数名:camelCase(例:starThreshold)
- 定数:UPPER_CASE(例:BLOCK_SIZE)
- 前後の行で = : , の位置揃えを行う
- 複数行に跨る () [] {} の位置揃えを行う
- 条件文は == <= < を用いることを原則とする
- 条件文で == の片辺が定数の場合、定数を左辺にすることを原則とする
- 条件文が複数行に跨る場合、and or を行の先頭に書く
- if elif else の分岐内で代入 が在る場合、すべての分岐で同じ変数を更新する
- if elif else の分岐内で return が在る場合、すべての分岐で return を行うこと(ただし関数先頭での引数検証での return は除く)
- 関数は単なる処理の分割や表面的な重複排除には利用しない
- 関数は本質的に同じ処理を一般化した上で作成する(過剰な一般化には注意する)

## データ型
- FlowData に保存する型を決定する為、numpy の一部処理(主に配列の生成)について numpy_helpers を用意しているのでこれを用いる

## コメント
- 文中にアルファベット表記の英単語を書く場合、前後に空白を入れる(例:色は rad とする)
- 文中に数値としての数字を書く場合、前後に空白を入れ単位を付ける(例:隙間を 8 px とする)
- if ブロックにコメントを付ける場合、if ブロック内に書く(例:None なので処理をスキップする)
- 1行に対する簡単なコメントは、コードの右に書く(例: datetime = data['datetime'] # 撮影時刻)

## ドキュメント
- 全メソッドに日本語 docstring を記述
- 複雑なアルゴリズムには詳細コメント
- パラメータの単位を明記(px, %, 度など)

## エラーハンドリング
- 原則として例外を捕まえて消し去ることは禁止
- ライブラリ内からのワーニングを隠蔽することは禁止
- 標準ライブラリ以外への依存機能は可用性チェック
- ユーザーフレンドリーなエラーメッセージ
- 設定値の妥当性検証


# コーディング規約の解説
- 条件文で == の片辺が定数の場合、定数を左辺にすることを原則とする
コードを読む際に定数が先に目付く方が分岐条件に早く理解できる。
また、elif が連続する場合、右辺側が埋もれて読み難いが、
左辺にあれば同じ列位置に定数が並ぶので読みやすくなる。

- if ブロックにコメントを付ける場合、if ブロック内に書く(例:None なので処理をスキップする)
elif ブロック、else ブロック が在る場合、場合分けでコメントが複雑になる。
ブロック内に書き、「X だったので Yする」と決定事項として書けば読み手の負荷が減る。
もちろん、if ブロックの前にもコメントを付けて if elif else 全体を通した概要も書くのが最も良い。
